# CV professional fixes integration review

## Result

No remaining integration blocker was found in the reviewed C02 and C04–C06 changes. This was a read-only review; no tests or rendering were run here.

## Evidence and limitations

- **Margins and preview:** Production PDFs use A4 `@page` margins of 48px top/bottom and 16px on the sides. Classic and Minimal keep 32px default zone padding with single-zone border-box sizing; PDF glyph measurements meet the 36pt default inset within fractional glyph tolerance. The saved `comfortable` 24px padding remains effective and retains the physical page margins. Preview geometry uses the same margins, ordinary long-document page-two starts match PDF extraction, and synthetic bottom-margin entries/headings move to the next page’s 48px content start. The body resize observer settled after one callback per fixture.
- **Modern sizing exception:** Modern intentionally retains its existing multi-zone content-box flex sizing because border-box narrowed the sidebar enough to break LinkedIn URL recovery. Its measured text insets are 30.62pt left and 29.46pt right, reflecting the seeded 24px padding plus the physical margin. This exception is now documented in the plan and margin handoff. Cross-template captures show the sidebar and main content contained within the page; both PDF parsers recover the LinkedIn address.
- **Oversized entries:** The notice is entry-specific, remains visible in the mobile capture, advises that the entry may split, and confirms export remains available. The stress fixture still has an acknowledged 5-page preview versus 6-page PDF because Chromium fragments the oversized entry internally; preview page-count parity is not promised for this case.
- **URLs and prompts:** `show_urls` defaults off, legacy labels remain unchanged unless enabled, visible addresses retain full normalized clickable destinations, and duplicate destination labels are not repeated. API tests cover user-profile and CV save/reload plus PDF text/URI recovery. The setting is included in tailoring’s owner contact injection and render-basis hash, with focused tests for owner precedence and stale-review reevaluation. Summary and experience prompts ask for factual, supportable details, suggest concise content, and avoid hard limits or invented claims.
- **UI evidence:** I inspected the existing 1280px and 390px profile-editor captures and the desktop/mobile preview captures. The URL option and prompts remain visible; the mobile preview has no horizontal overflow, and the oversized-entry notice remains readable.

The initial backend run’s four Modern LinkedIn extraction failures and one Minimal edge-distance assertion were addressed in the final changes: multi-zone sizing was preserved, and the stress test now asserts physical margins while retaining title/date/company/body attachment checks. The affected subset is reported passing (69 tests), alongside the two focused tailoring regressions. The final full backend and smoke gates were still running when this review was written. The Modern report’s exact contiguous-name probe is false because the name wraps/interleaves across columns; the glyphs are visible and the existing readability test locates/measures the words independently. External ATS products were not tested.
